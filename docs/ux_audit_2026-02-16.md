# UX Audit Report — Inspirations Frontend

**Date:** 2026-02-16
**Auditor:** Claude (Senior UX Engineer Review)
**Scope:** `app/index.html`, `app/styles.css`, `app/app.js`, `app/admin.html`, `app/admin.js`
**Purpose:** Identify visual hierarchy, spacing, accessibility, and modern UI best practice issues before making any code changes.

---

## Executive Summary

The Inspirations frontend is a dark-themed, three-column layout built with vanilla HTML/CSS/JS. It is functional and ships several good patterns (CSS custom properties, responsive breakpoints, slide-out mobile drawers, lazy loading). However, the UI suffers from **toolbar button overload**, **flat visual hierarchy** due to uniform small font sizes, **significant accessibility gaps**, and **inconsistent spacing via inline styles**. The following report catalogs 28 findings across four audit categories, each with a severity rating.

**Severity Scale:**
- **Critical** — Blocks users or violates WCAG 2.1 Level A
- **High** — Degrades experience significantly or violates WCAG 2.1 Level AA
- **Medium** — Noticeable quality gap vs. modern UI standards
- **Low** — Polish issue or minor inconsistency

---

## 1. Visual Hierarchy

### VH-1: Flat Font Size Scale (Medium)

Nearly all text in the application falls in a narrow 11px-14px range. The app title is 14px, section titles are 12px, card titles are 13px, and body text is 12px. This creates a **flat reading experience** where nothing visually "pops" as a primary heading or focal point.

- `.title` — 14px
- `.sectionTitle` — 12px
- `.cardTitle` — 13px (font-weight 600)
- `.cardSummary` — 12px
- `.cardMeta` — 12px
- `.chip` — 10px
- `.tagTitle` — 10px
- `.badge` — 11px
- `.muted` — 12px

**Recommendation:** Establish a proper type scale (e.g., 11 / 13 / 15 / 18 / 22px) with clear roles. Section headings should be at least 14-16px. The app brand title should be 18-20px. Card titles should be at least 14px on desktop.

### VH-2: Toolbar Button Overload (High)

The main content toolbar (lines 76-97 in `index.html`) contains **13+ buttons** in two rows:

**Row 1 (toolbarMeta):**
- "AI Tags: Any" toggle
- "Create Collection"
- "Add Tray to Collection"
- "Clear Tray"

**Row 2:**
- "Select All"
- "Add Selected to Collection" (primary)
- "Add Selected to Tray"
- "Remove Selected from Collection"
- "Remove Selected from Tray"
- "Add Filtered"
- "Clear Selection"
- "Review Collection"
- "Show Tray Canvas"
- "Show All"

This violates the **progressive disclosure** principle. Users are confronted with every possible action simultaneously, most of which are disabled at any given moment. The cognitive load is very high.

**Recommendation:** Group actions into a primary toolbar (3-4 most common actions) and use a "More Actions" overflow menu or contextual action bar that appears only when items are selected.

### VH-3: Disabled Buttons Dominate the Toolbar (Medium)

Most toolbar buttons start `disabled` and only become active in specific states. The toolbar is full of grayed-out buttons that create visual noise without providing value. On initial load, approximately 10 of 13 buttons are disabled.

**Recommendation:** Hide actions that are not applicable to the current context rather than showing them disabled. Use `hidden` or `display: none` and reveal contextually. Reserve `disabled` for buttons that are *almost* ready (e.g., "Import" button before a file is selected).

### VH-4: No Clear Visual Separation Between Toolbar Zones (Low)

The toolbar's `toolbarMeta` and the main action `row` have no visual boundary. Both rows blend into a continuous sea of buttons.

**Recommendation:** Add a subtle divider, background differentiation, or grouping containers to visually separate "view controls" from "selection actions".

### VH-5: Card Footer Metadata is Cryptic (Medium)

Card footers show `AI: gemini-2.5-flash • 47 tags`. While useful for power users, "AI: —" on untagged items and raw model names are unclear for general users.

**Recommendation:** Simplify to a status indicator (e.g., "Tagged" / "Not tagged" badge) and move detailed model info to the expanded view only.

## 2. Spacing & Layout

### SP-1: Pervasive Inline Styles (High)

The HTML contains at least **8 inline `style` attributes** for spacing:

- `style="margin-top: 8px"` (lines 67, 113)
- `style="margin-top: 6px"` (lines 71, 119, 203)
- `style="margin-top: 10px"` (line 100)
- `style="margin-top: 12px"` (line 201)
- `style="flex-wrap: wrap"` (line 113)

These bypass the design system and make spacing inconsistent and hard to maintain.

**Recommendation:** Define spacing utility classes (`.mt-1`, `.mt-2` or `.space-sm`, `.space-md`) or use the existing `.section` padding rhythm consistently. Remove all inline `style` attributes from the HTML.

### SP-2: Inconsistent Gap Values (Medium)

Gap values across the layout lack a consistent scale:
- `.actions` — `gap: 8px`
- `.searchInputRow` — `gap: 6px`
- `.list` — `gap: 8px`
- `.grid` — `gap: 10px`
- `.cardBody` — `gap: 8px`
- `.chips` — `gap: 6px`
- `.compactTags` — `gap: 6px`
- `.modalBody` — `gap: 12px`
- `.toolbar` (mobile) — `gap: 10px`

**Recommendation:** Standardize on a 4px-based spacing scale (4, 8, 12, 16, 24, 32px) and use it consistently. Most of the current values are close but not uniform.

### SP-3: Sidebar Width Discrepancy (Low)

`.layout` defines sidebars at `280px` but `.layout.three` overrides to `260px`. This means the sidebar width changes depending on whether the tray is visible, which can cause a jarring layout shift.

**Recommendation:** Use a single consistent sidebar width or animate the transition.

### SP-4: Mobile Grid Drops to Fixed 2-Column (Medium)

At `max-width: 700px`, the grid switches from `auto-fill, minmax(200px, 1fr)` to a hard-coded `repeat(2, minmax(0, 1fr))`. On very narrow screens (< 400px, e.g., iPhone SE), cards become cramped at ~180px each.

**Recommendation:** Allow the grid to fall to 1 column on very narrow viewports. Add a breakpoint at ~400px or use `auto-fill` with a smaller `minmax` (e.g., `minmax(150px, 1fr)`).

### SP-5: Modal Image Stage Fixed Aspect Ratio (Medium)

The `.imageStage` has a hard-coded `aspect-ratio: 4/3`. For panoramic or portrait images, this wastes significant vertical or horizontal space.

**Recommendation:** Let the image stage height be content-driven with a `max-height` constraint, or use `object-fit: contain` inside a flexible container.

### SP-6: Admin Page Has No Layout Shell (Low)

`admin.html` uses `class="adminShell"` but no CSS defines `.adminShell`. The admin content has no max-width constraint and stretches edge-to-edge on wide monitors.

**Recommendation:** Add a `.adminShell` rule with `max-width: 800px; margin: 0 auto; padding: 24px;` or similar.

## 3. Accessibility

### A-1: No Skip Navigation Link (High)

There is no "skip to main content" link. Keyboard users must tab through the entire header, search bar, all sidebar filters, and collection items before reaching the asset grid.

**Recommendation:** Add a visually hidden skip link as the first focusable element: `<a class="skip-link" href="#grid">Skip to content</a>`.

### A-2: Color Contrast Ratios Below WCAG AA (Critical)

The dark theme's muted text color `rgba(255,255,255,0.68)` on `#0b0f14` background yields approximately **7.5:1 contrast ratio** — this passes. However, several elements fall below WCAG AA (4.5:1 for normal text, 3:1 for large text):

- `.chip` text (10px, inherits `--text` at 0.92 opacity) on `rgba(255,255,255,0.08)` background — the chip background is nearly transparent, so contrast depends on the parent. On `rgba(15,23,34,0.55)` card body, the effective background is very dark and likely passes. **However**, `.chip.empty` uses `--muted` color with `transparent` background and `dashed` border — this 10px text at 0.68 opacity on very dark backgrounds may be borderline.
- `.badge` (11px) uses inherited `--text` on `rgba(11,15,20,0.65)` which overlays the image — **contrast is image-dependent and unreliable**.
- `.filterItem.zeroOption` at `opacity: 0.55` — this reduces an already-small 12px text to approximately `0.55 * 0.92 = 0.51 opacity`, which is **severely low contrast**.
- Placeholder text `rgba(222, 234, 246, 0.78)` on `rgba(18, 30, 46, 0.9)` — approximately 6:1, passes AA.

**Recommendation:** Remove the `opacity: 0.55` pattern on `.zeroOption` (use a distinct muted color instead). Ensure `.badge` has a solid background or sufficient minimum contrast. Audit all text/background combinations with a contrast checker tool.

### A-3: Missing ARIA Labels on Interactive Elements (High)

Many buttons lack descriptive accessible names:

- `<button id="newCollection">New</button>` — "New" is ambiguous without context
- `<button id="deleteCollection">Delete</button>` — "Delete" what?
- `<button id="selectAll">Select All</button>` — Select all what?
- `<button id="closeModal">Close</button>` — Close what?
- `<button id="loadMore" hidden>Load More</button>` — Load more what?
- Annotation delete button: `<button class="iconBtn danger" data-del="${ann.id}">x</button>` — the "x" text is not screen-reader friendly
- Checkboxes inside cards have no associated `<label>` text — they're wrapped in a `<label class="selectBox">` but the label contains no text content

**Recommendation:** Add `aria-label` attributes to all buttons with ambiguous text content. Ensure all form controls have associated labels.

### A-4: No Focus Management on Modal Open/Close (High)

When the asset detail modal opens (`openModal()`), focus is not programmatically moved to the modal. When it closes (`closeModal()`), focus is not returned to the triggering element. This means keyboard users lose their place in the document.

**Recommendation:** On open, move focus to the modal's close button or first interactive element. On close, return focus to the element that triggered the modal (the Annotate button or card). Add `tabindex="-1"` to the modal content wrapper.

### A-5: No Focus Trap in Modals (Critical)

The modal (`#modal`, `#scanImportModal`, `#photoImportModal`) does not trap focus. Keyboard users can Tab past the modal into the background page content, which is visually obscured by the overlay.

**Recommendation:** Implement a focus trap that constrains Tab/Shift+Tab cycling within the modal while it's open. Consider using the native `<dialog>` element which provides this for free.

### A-6: Grid Cards Not Keyboard Accessible (Critical)

Cards in the grid are `<div>` elements with only `onclick` handlers. They are **not focusable** via keyboard (no `tabindex`, no `role="button"`, no keyboard event handlers). A keyboard-only user cannot expand a card or navigate the grid.

**Recommendation:** Add `tabindex="0"` and `role="button"` to cards (or use `<button>` elements). Add `keydown` handlers for Enter and Space. Consider `role="grid"` with `role="gridcell"` for arrow-key navigation.

### A-7: Annotations Delete Without Confirmation (Medium)

The annotation sidebar delete button (`x`) immediately deletes via API call with no confirmation dialog or undo mechanism. This is a destructive action triggered by a tiny 22x22px button.

**Recommendation:** Add a confirmation step, or better, implement an undo toast pattern.

### A-8: No Visible Focus Indicators (High)

The CSS does not define custom `:focus` or `:focus-visible` styles for buttons, list items, or cards beyond the browser default. The browser default `outline` is often invisible against the dark background (especially in Chrome which uses a thin blue outline).

**Recommendation:** Add explicit `:focus-visible` styles with sufficient contrast. Example: `outline: 2px solid var(--accent); outline-offset: 2px;`.

### A-9: Image Alt Text is Empty (Medium)

All `<img>` elements in cards use `alt=""`. While this is technically valid for decorative images, these images are the **primary content** of the application. Screen reader users get no information about what each card contains.

**Recommendation:** Use the AI summary or title as alt text: `alt="${escapeHtml(displayTitle(a))}"`. Fall back to `alt="Inspiration image"` if no title exists.

### A-10: Search Help Tooltip Not Announced (Medium)

The search help tooltip (`#searchHelpTooltip`) uses `role="tooltip"` and is linked via `aria-controls`, but it is shown/hidden via CSS `display: none/block` without any `aria-live` region or programmatic announcement.

**Recommendation:** The current ARIA pattern is reasonable for a tooltip. Ensure the tooltip content is also accessible when the `?` button receives focus (the `:focus-within` rule in CSS does handle this).

### A-11: Inline Event Handlers on Collection Items (Low)

Collection list items use `el.onclick = async () => {...}`. These are `<div>` elements without `role="button"` or `tabindex="0"`, making them inaccessible to keyboard users.

**Recommendation:** Make collection items focusable with keyboard support, same as cards (A-6).

## 4. Modern UI Best Practices

### UI-1: Entire Grid Rebuilt on Every Interaction (High)

`renderGrid()` sets `wrap.innerHTML = ""` and rebuilds all cards from scratch on every selection toggle, expand/collapse, and load. With 240 items (`ASSETS_PAGE_SIZE`), this causes noticeable layout thrash, scroll position loss, and image re-requests.

**Recommendation:** Use targeted DOM updates. Toggle `.selected` and `.expanded` classes on existing elements instead of destroying and recreating them. For data changes, use a reconciliation approach or virtual DOM library.

### UI-2: No Loading Skeleton or Spinner (Medium)

Initial load shows "Loading..." text in the stats area and "Loading filters..." in the sidebar. There are no skeleton placeholders, shimmer animations, or spinner indicators for the grid area.

**Recommendation:** Add skeleton cards (gray placeholder rectangles matching card layout) during initial load and "Load More" fetches. This provides spatial context and reduces perceived load time.

### UI-3: Alert-Based Notifications (Medium)

Import results, errors, and delete confirmations all use native `alert()` and `confirm()` dialogs. These block the UI thread, cannot be styled, and are jarring.

**Recommendation:** Replace `alert()` with toast notifications for success/info messages. Replace `confirm()` with inline confirmation UI or a styled dialog. Keep `confirm()` only for destructive actions if styled modals are not yet implemented.

### UI-4: No Undo for Destructive Actions (Medium)

Clearing the tray, removing items from collections, and hiding assets are all immediate with no undo option. The user must re-perform multi-step workflows to recover.

**Recommendation:** Implement a temporary undo toast (e.g., "Removed 3 items. Undo") for collection and tray operations. The 5-10 second undo window is a well-established pattern.

### UI-5: Admin Page Duplicates Utility Functions (Medium)

`admin.js` redefines `escapeHtml()` and `api()` with slightly different implementations:
- `escapeHtml()` uses `replaceAll()` instead of `.replace(/&/g, ...)`
- `api()` adds an admin-token header parameter

This creates maintenance risk and inconsistent behavior.

**Recommendation:** Extract shared utilities (`escapeHtml`, `api`, `formatApiError`) into a `shared.js` module loaded by both pages.

### UI-6: Hardcoded User Name in Title Processing (High)

`displayTitle()` in `app.js` (line 451) contains a hardcoded personal name:
```
title = title
  .replace(/^leslie brannigan saved a (?:link|product|video)(?: from)?\s+/i, "")
```

This is user-specific logic baked into the shared application code, making the app non-portable.

**Recommendation:** Either remove the name stripping entirely (display Facebook titles as-is) or make it configurable via a settings endpoint or config file.

### UI-7: No Empty State Design (Medium)

When no items match filters, the grid shows a single line of muted text: "No items match current filters." There is no illustration, helpful suggestion, or call to action.

**Recommendation:** Design an empty state with an icon/illustration, primary message, and actionable suggestion (e.g., "Try clearing some filters" button, or "Import your first items" call to action when the database is empty).

### UI-8: Mobile Toolbar Horizontal Scroll Without Affordance (Medium)

At `max-width: 700px`, the toolbar row switches to `overflow-x: auto; flex-wrap: nowrap`. There is no visual indicator (fade edge, scroll shadow, or arrow) that more buttons exist off-screen.

**Recommendation:** Add a CSS gradient fade or scroll shadow on the right edge to signal scrollable content. Example: `mask-image: linear-gradient(to right, black 90%, transparent)`.

### UI-9: Admin Link Hidden on Mobile (Low)

At `max-width: 700px`, `.adminNav { display: none; }`. Mobile users have no way to access the admin page.

**Recommendation:** Keep the admin link accessible on mobile, perhaps in a hamburger menu or at the bottom of the sidebar.

## Recommended Fix Priority

### Phase 1 — Critical Accessibility (A-2, A-5, A-6)
Address WCAG Level A violations: contrast fixes, focus trapping in modals, and keyboard access to grid cards. These are the most impactful for users with disabilities and are often considered legal compliance requirements.

### Phase 2 — High-Impact UX (VH-2, UI-1, A-4, A-8, SP-1)
Reduce toolbar button overload, fix the grid rebuild performance issue, add focus management and visible focus indicators, and remove inline styles.

### Phase 3 — Accessibility Polish (A-1, A-3, A-9, A-11)
Add skip navigation, ARIA labels, meaningful image alt text, and keyboard support for collection items.

### Phase 4 — Modern UX Patterns (UI-2, UI-3, UI-4, UI-6, UI-7, VH-1)
Replace alerts with toasts, add loading skeletons, implement undo, remove the hardcoded username, design empty states, and establish a proper type scale.

### Phase 5 — Polish (remaining Medium/Low items)
Standardize spacing scale, improve mobile grid behavior, add scroll affordances, extract shared admin utilities.

## Positive Patterns Observed

While this audit focuses on issues, the following are good practices already in place:

1. **CSS Custom Properties** — Colors and theme values use `--bg`, `--panel`, `--accent` variables, enabling easy theme changes.
2. **Responsive Breakpoints** — Three-tier responsive design (desktop > 1100px, tablet > 700px, mobile) with slide-out drawers.
3. **Lazy Loading Images** — Cards use `loading="lazy"` for off-screen images.
4. **Semantic Modal ARIA** — Import modals have `role="dialog"`, `aria-modal="true"`, and `aria-labelledby`.
5. **XSS Protection** — All dynamic text is passed through `escapeHtml()` before insertion.
6. **Mobile Overlay** — The background overlay on mobile drawer open provides clear visual context.
7. **Progressive Image Fallback** — Failed image loads are replaced with text placeholders.
8. **Search Help Tooltip** — The `?` button with tooltip pattern is discoverable and non-intrusive.
