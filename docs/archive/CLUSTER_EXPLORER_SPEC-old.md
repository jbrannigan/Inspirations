# Cluster Explorer — Feature Specification

> Status: archived draft; superseded by `docs/CLUSTER_EXPLORER_SPEC-v2.md`.

## Overview

A browser-based visual exploration tool for Leslie's curated inspiration collections.
Renders semantic clusters as a force-directed graph where **nodes are actual thumbnail
images** (not colored dots), draggable and zoomable, with three distinct interaction modes.

The explorer loads data exported from the Inspirations DB and runs entirely client-side
(single HTML file + a JSON data export). No server dependency required, though it can
optionally call the live API for real-time similarity search.

## Data Pipeline

### Export Script: `tools/export_clusters.py`

Already exists. Needs these additions:

1. **Include thumbnail paths** in node data (already has `thumb_url` and `image_url`
   fields — just need to ensure `stored_path` / `thumb_path` are resolved to absolute
   file:// URLs or relative paths the browser can load).

2. **Include `source_url`** (original Pinterest/Facebook URL) for "open original" links.

3. **Compute outlier scores** per node:
   - `isolation_score`: inverse of mean similarity to k-nearest neighbors (higher = weirder)
   - `bridge_score`: how much a node connects two otherwise-separate clusters
     (betweenness-centrality-lite: count of cross-cluster edges through this node)

4. **Flag cluster centroids** (already done) and **outliers** (top 10% isolation score).

5. **Add `--collection` filter** flag to export just one collection's items + their
   nearest uncategorized neighbors (for Mode 3 focused curation).

## Explorer UI: `tools/cluster_explorer.html`

Single self-contained HTML file. Dependencies loaded from CDN:
- D3.js v7 (force simulation, zoom, drag)
- No build step, no framework

### Image Nodes

Replace colored circles with actual thumbnails:
- Render each node as a `<clipPath>` circle masking the thumbnail image
- Circle diameter: 40px default, 56px for centroids, 32px for low-neighbor nodes
- Border color = collection color (from palette)
- Border width: 3px for centroids, 2px for selected, 1px default
- Fallback: if image fails to load, show colored circle with first letter of title
- Hover: scale up 1.5x with CSS transition, show tooltip

### Performance for 3,600+ Nodes

- Use `<canvas>` renderer instead of SVG for the main graph when node count > 500
  (D3 force simulation works the same, just draw to canvas instead of DOM manipulation)
- Lazy-load images: only load thumbnails for nodes currently in the viewport
- Use IntersectionObserver pattern adapted for the zoom/pan transform
- Thumbnail size: 240px (already generated by Inspirations' thumb pipeline)
- Consider WebGL (via regl or pixi.js) if canvas is still slow at 3,600 nodes

### Three Modes

#### Mode 1: Discover ("How cool is this")

The default view. Full graph, all nodes visible, force simulation running.

- **Layout**: Force-directed with similarity-based attraction
- **Interaction**: Drag nodes, zoom/pan, click for detail panel
- **Legend**: Collection colors, click to toggle visibility
- **Search**: Filter by label/title/board text — matching nodes brighten, others fade
- **Fun feature**: "Shake" button that reheats the simulation so everything bobbles

This is essentially what exists today, but with images instead of dots.

#### Mode 2: Outliers ("Explore the weirdos")

Activated via toolbar button. Highlights unusual items.

- **Sort/filter by isolation score**: Slider to control "weirdness threshold"
- **Visual treatment**: Outliers glow (pulsing animation), non-outliers fade to 20% opacity
- **Bridge nodes**: Nodes connecting different clusters get a distinct ring (gold?)
- **"Lonely items" list**: Sidebar showing the most isolated items as a scrollable
  thumbnail grid, sorted by isolation score descending
- **Suggested actions**: "This doesn't belong anywhere" → option to flag for removal
  or "This could be its own theme" → option to seed a new collection from it + neighbors

#### Mode 3: Curate ("Focus on a collection")

Activated by clicking a collection in the legend (or toolbar dropdown).

- **Isolation view**: Only shows the selected collection's items + optionally their
  nearest uncategorized neighbors (toggle: "Show nearby uncategorized")
- **Layout**: Re-runs force simulation with just the filtered set for tighter grouping
- **Sub-clusters**: Within the collection, show internal groupings
  (e.g., within "CB: Kitchen": white kitchens, dark kitchens, rustic kitchens)
  as labeled regions or subtle background halos
- **Selection tools**:
  - Click to select/deselect individual items
  - Lasso select (click-drag on empty space draws a freeform selection)
  - "Select cluster" button to select all items in a sub-cluster
- **Tray**: Selected items drop into a tray at the bottom of the screen
  - Shows selected thumbnails as a horizontal strip
  - Count display: "12 of 80 selected"
  - Actions: "Keep selected (remove rest)", "Remove selected", "Export selection"
- **Result**: The final curated set — Leslie's actual top picks per theme
- **Export**: Save selection as a new collection in the DB (via API call to
  `POST /api/collections` if running against live server, or export as JSON for
  the standalone script to import)

### Toolbar

Persistent across all modes. Left-aligned items:

```
[Discover] [Outliers] [Curate ▾]  |  Search: [________]  |  3,661 items  10,924 links  14 clusters
```

- Mode buttons are radio-style (one active at a time)
- "Curate ▾" shows dropdown of collections to focus on
- Search is always available

### Detail Panel (Right Sidebar)

Slides in on node click. Shows:
- Full-size image (loaded from `image_url` or `stored_path`)
- Title, board, source
- Collection membership badges
- AI summary
- All labels as chips
- Nearest neighbors as thumbnail strip (clickable to navigate)
- Isolation score bar
- "Open original" link (Pinterest/Facebook URL)
- In Curate mode: "Select" / "Remove" buttons

### Tooltip (Hover)

- Thumbnail preview (larger than node, ~160px)
- Title
- Collection name
- Top 5 labels

## Image Loading Strategy

The key challenge: `file://` protocol has CORS restrictions that prevent loading
local images from an HTML file. Three approaches in order of preference:

### Option A: Built-in HTTP server (recommended)

Add a `--serve` flag to the export script or a separate serve command:

```bash
python3 tools/serve_explorer.py --port 8080
```

This starts a simple HTTP server that:
1. Serves `cluster_explorer.html` at `http://localhost:8080/`
2. Serves image files from the data directory
3. Serves `cluster_data.json` (auto-loads on page open, no file picker needed)

Implementation: ~30 lines of Python using `http.server` with custom handler.

### Option B: Embed as data URIs

The export script reads each thumbnail, base64-encodes it, and embeds it in the JSON
as `thumb_data: "data:image/jpeg;base64,..."`. This makes the JSON large (~200-400MB
for 3,600 images) but works without any server. Not recommended for this scale.

### Option C: Integration with existing Inspirations server

The Inspirations app already serves at `http://minime.local:8000`. The explorer
could load images from `/images/<asset_id>` or `/thumbs/<asset_id>` endpoints.
Add a `--api-base` flag:

```bash
# Explorer fetches images from the live server
python3 tools/export_clusters.py --api-base http://minime.local:8000
```

This writes the API base URL into the JSON meta, and the explorer prepends it to
all image paths. Best of both worlds: small JSON, live images, no CORS issues
(same-origin if served from same host, or add CORS headers to the Inspirations server).

**Recommendation**: Option A for standalone use, Option C for integration with the
running Inspirations server. Support both via the `meta.image_base_path` or
`meta.api_base` field in the JSON.

## CLI Integration

### New subcommand: `inspirations explore`

```bash
# Export + serve in one step
python3 -m inspirations explore \
  --similarity-threshold 0.72 \
  --max-neighbors 6 \
  --clusters auto \
  --port 8080

# Export a single collection for focused curation
python3 -m inspirations explore \
  --collection "CB: Kitchen" \
  --include-neighbors 20 \
  --port 8080
```

This:
1. Runs the export (same logic as `export_clusters.py`)
2. Writes the JSON to a temp file
3. Starts the HTTP server
4. Opens the browser to `http://localhost:8080/`

### Write-back from Curate mode

When Leslie/Jim finishes curating in Mode 3 and clicks "Save selection":

- **If running via `inspirations explore`**: POST to a local endpoint that writes
  directly to the DB (create/update collection, add/remove items)
- **If standalone HTML**: Export selection as JSON that can be imported via
  `python3 -m inspirations curate --import selection.json`
